## Главные выводы
1. if/else - универсальный инструмент, switch/case - удобен для сравнения одной переменной с конкретными значениями

2. int.TryParse() безопаснее int.Parse(): он не выбрасывает исключение при неверном вводе, а возвращает false. Это критично для программ, работающих с пользовательским вводом

3. Тернарный оператор - только для простых случаев. Если условий больше двух или логика сложная - читаемость падает, лучше использовать обычный if/else.

## Ответы на вопросы
**1. Чем int.TryParse() безопаснее int.Parse()? В каких случаях стоит использовать 
каждый?**

int.Parse() выбрасывает исключение FormatException, если строка не является числом. Это может привести к аварийному завершению программы. int.TryParse() возвращает bool (успех/неудача) и записывает результат в переменную через out.

**2. Когда switch удобнее, чем цепочка if/else if? Приведите пример из реальной жизни.**

switch удобнее, когда одна переменная сравнивается с конкретными значениями (числа, строки, символы). Пример: меню в банкомате - «1 - снять наличные, 2 - пополнить, 3 - проверить баланс, 4 - выйти». Длинная цепочка if/else if здесь выглядела бы громоздко и хуже читалась.

**3. Что произойдёт в switch, если убрать break после одного из case?**

Выполнение «провалится» в следующий case и продолжит выполняться до первого break или конца switch. В C# это разрешено только для пустых case. Если в case есть код и нет break - компилятор выдаст ошибку.

**4. Чем отличается = от == в C#? Почему это частая ошибка?**

=  оператор присваивания: x = 5 записывает 5 в переменную x.
==  оператор сравнения: x == 5 проверяет, равно ли x пяти.

Это частая ошибка, потому что в математике = означает равенство, и новички по привычке пишут if (x = 5) вместо if (x == 5). В C# это приведёт к ошибке компиляции (нельзя присвоить значение в условии, если результат не bool).

**5. Можно ли написать тернарный оператор внутри другого тернарного оператора?**

Читаемость такого кода низкая: сложно быстро понять, какое условие за что отвечает. Для двух уровней вложенности ещё допустимо, для трёх и более - лучше использовать if/else или switch.
